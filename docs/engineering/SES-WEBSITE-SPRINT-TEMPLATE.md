## Mission

## Frozen inputs

## Business value

## Scope

List included pages, components, assets, languages and machine-facing surfaces.

## Out of scope

Explicitly prevent redesign, feature expansion or adjacent engineering work from entering the Sprint unintentionally.

## Tasks

For each task define:

- Objective
- Required changes
- Constraints
- Evidence
- Acceptance criteria

## QA

Verify:

- Desktop
- Tablet
- Mobile
- Chinese
- English
- Navigation
- CTA buttons
- Internal links
- Placeholder content
- Broken pages
- Terminology consistency
- Metadata and structured data
- Type check, lint and build

## Deliverables

### A. Sprint Summary

List every completed task, modified file and verification result.

### B. Remaining Issues

List file or asset, location, reason, owner, risk and next action.

### C. Next Sprint Recommendations

Recommend future improvements without implementing them.

## Sprint rules

- Do not change frozen inputs.
- Do not hide unresolved defects.
- Do not expand scope without a recorded decision.
- Do not confuse build success with product-delivery success.

## Release gate

List binary conditions. Every condition must be verified before completion.

## Executive review

Define the questions a first-time enterprise visitor must answer within ten seconds.

## Final status

End with exactly one binary status:

- `Sprint Status: COMPLETE — all release gates verified.`
- `Sprint Status: OPEN — unresolved release gates listed above.`

## Freeze declaration

Once approved, freeze the Sprint specification. Any change requires a superseding version and explicit change record.
