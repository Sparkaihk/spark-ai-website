# SES-001 — Website Brand Migration Specification V1.0

**Sprint:** Sprint 1 — Brand Migration  
**Status:** Active  
**Owner:** Website Engineering  
**Brand authority:** SB-001 Brand OS  
**Product authority:** SPR-001 Spark AI Appliance™ PRD

## Mission

Implement the official Spark AI Brand OS V1.0 across the entire website.

This Sprint is **not** a redesign.

This Sprint is **not** about adding features.

This Sprint is only about delivering a complete, consistent, enterprise-grade Brand Migration.

The website must become a trustworthy representation of Spark AI.

## Frozen Brand OS — Do Not Change

### Company

**Spark AI Technology Limited**

### Chinese name

**光慧科技有限公司**

### Brand

**Spark AI™**

### Platform

**Spark AI Knowledge Infrastructure**

### Flagship product

**Spark AI Appliance™**

### Website

**Spark AI Headquarters**

### Positioning

**The Knowledge Infrastructure for the AI Era**

### Brand manifesto

**Memory for AI. Trust for Tomorrow.**

These names and statements are frozen.

Do not rename. Do not rewrite. Do not replace.

## Sprint scope

Complete a full Brand Migration across the entire website.

Included surfaces:

- Homepage
- Navigation
- Footer
- Spark AI Appliance™
- Solutions
- Research
- Headquarters
- About
- Contact
- Metadata
- SEO
- Open Graph
- Structured Data

Do not create new public pages.

Do not redesign layouts unless a minimal adjustment is required to restore naming, typography or component consistency.

## Out of scope

- New product functionality
- New public routes
- New marketing sections unrelated to migration
- New animation concepts
- New visual identity directions
- Product-definition changes
- Architecture changes
- Unrelated performance refactoring
- Bulk asset relocation without a direct migration need

## Task 1 — Global Brand Audit

Review every user-facing page and shared component.

Find every inconsistency involving:

- Brand names
- Product names
- Platform names
- Website identity
- Positioning and manifesto
- Terminology
- Typography
- Colors
- Logos
- Icons
- Buttons
- Footer
- Metadata

Correct every inconsistency within Sprint scope.

### Required audit record

For each issue, record:

- File path
- Line number
- Current value
- Approved replacement
- Surface
- Status
- Review notes or reason retained

Compatibility routes, filenames and internal IDs may remain only when they are not visible to users and their immediate replacement would break existing links or assets.

## Task 2 — Terminology Standardization

Use only the following official names:

- Spark AI™
- Spark AI Knowledge Infrastructure
- Spark AI Appliance™
- Spark AI Headquarters

Replace all legacy visible wording.

Maintain supplier, model, hardware and software terms only where technically necessary and factually accurate.

Technology suppliers must never replace the Spark AI product identity.

### Trademark usage

Use the trademark symbol on the first prominent occurrence of a protected name per page or major document. Avoid visually noisy repetition in every sentence.

## Task 3 — Homepage

The Hero must answer:

1. Who is Spark AI?
2. What does Spark AI build?
3. Why does it matter?

The homepage must immediately establish Spark AI as the company building **The Knowledge Infrastructure for the AI Era**.

Avoid excessive marketing language.

Focus on clarity and trust.

### Required homepage hierarchy

- Brand: Spark AI™
- Platform: Spark AI Knowledge Infrastructure
- Positioning: The Knowledge Infrastructure for the AI Era
- Product relationship: Spark AI Appliance™ as the flagship product
- Manifesto: Memory for AI. Trust for Tomorrow.
- Clear primary and secondary actions

Do not add a new homepage section solely to repeat these messages. Use the existing information architecture.

## Task 4 — Navigation

Global navigation must become:

1. Home
2. Knowledge Infrastructure
3. Spark AI Appliance™
4. Solutions
5. Research
6. Headquarters
7. About
8. Contact

Desktop and mobile navigation must use the same ordered source configuration.

Every link must resolve to an existing valid destination. If the approved label does not have a dedicated route, map it to the most appropriate existing route without creating a new public page, and record the mapping for Product review.

## Task 5 — Footer

Footer must consistently display:

- Spark AI Technology Limited
- 光慧科技有限公司 where Chinese company identity is shown
- Spark AI Headquarters
- Navigation
- Contact
- Copyright

Remove outdated wording and legacy product identity.

Footer navigation should derive from the same approved naming architecture as the global navigation, while allowing footer-specific grouping.

## Task 6 — Visual Consistency

Review the entire website for consistency in:

- Typography
- Spacing
- Buttons
- Cards
- Illustrations
- Animations
- Icons
- Logo placement
- Colors
- Glass UI

Maintain the premium light-blue design language.

### Migration boundary

Visual work in this Sprint is corrective, not exploratory.

Allowed:

- Align duplicated button states
- Correct mismatched fonts, spacing or colors
- Normalize logo sizing and placement
- Remove legacy product labels embedded in visuals
- Correct inconsistent glass treatment
- Restore responsive consistency after copy changes

Not allowed:

- New page composition
- New decorative animation
- New illustration direction
- Replacing working components solely for aesthetic preference

## Task 7 — Metadata

Review every indexable page and standardize:

- Page title
- Description
- Open Graph title
- Open Graph description
- Open Graph image
- Twitter Card
- Canonical URL
- Structured Data
- Favicon
- Site Manifest
- SEO keywords

### Metadata principles

- Titles identify the page and Spark AI clearly.
- Descriptions communicate actual page value without keyword stuffing.
- Product metadata uses Spark AI Appliance™.
- Platform metadata uses Spark AI Knowledge Infrastructure.
- Website identity uses Spark AI Headquarters where appropriate.
- Structured Data matches visible content.
- Canonical URLs resolve correctly.
- Social images contain no legacy naming.

## Task 8 — Brand Asset Review

Review user-facing assets for embedded legacy identity:

- Logos
- Product renders
- SVG diagrams
- Social cards
- Favicons
- Manifest icons
- PDF covers
- Download thumbnails
- Image captions and alt text

If a raster image contains an incorrect visible name, changing alt text is insufficient. Record it for regeneration or replace it with an approved asset during the Sprint when possible.

Do not rename internal asset paths unless every importer is updated and verified.

## Task 9 — Bilingual Consistency

English and Chinese surfaces must express the same Brand OS.

Required checks:

- Navigation
- Hero
- Product naming
- CTA
- Footer
- Page titles and descriptions
- Image alt text where localized
- Contact and company identity

Keep the following names unchanged across languages:

- Spark AI™
- Spark AI Knowledge Infrastructure
- Spark AI Appliance™
- Spark AI Headquarters

Preserve the Chinese legal company name exactly:

**光慧科技有限公司**

## Task 10 — Verification

### Source verification

Search user-facing source files incrementally by section. Do not allow generated directories to block the migration.

Ignore:

- `node_modules/`
- `.next/`
- `dist/`
- `coverage/`
- `build/`

Every remaining legacy reference must include:

- File path
- Line number
- Reason
- Classification: visible content, technical necessity, compatibility route, asset path, historical record or manual review

### Functional verification

- Desktop navigation
- Mobile navigation
- All navigation destinations
- Homepage actions
- Product actions
- Contact actions
- Footer links
- Language switching
- Downloads
- Canonical URLs

### Technical verification

- Type check
- Lint
- Production build
- No hydration errors
- No console errors
- No new horizontal overflow
- No new layout shift caused by migrated copy

## Acceptance criteria

Sprint 1 is complete only when:

1. All user-visible brand names match the Frozen Brand OS.
2. No visible legacy product name remains.
3. Homepage clearly establishes company, platform and value.
4. Desktop and mobile navigation use the approved labels and order.
5. Footer contains the approved company and Headquarters identity.
6. Metadata and structured data match visible page identity.
7. Product images, captions and alt text use the approved naming.
8. English and Chinese surfaces are semantically consistent.
9. Every retained legacy reference has file, line and reason.
10. All existing routes and required links work.
11. Type check, lint and production build pass.
12. The final report lists every modified file and every unresolved exception.

## Decision authority

The Frozen Brand OS in this specification cannot be changed within Sprint 1.

Any proposed change requires a new Brand OS decision through SPK-FS-003 Decision Process and explicit approval from the Brand and Corporate owners.
